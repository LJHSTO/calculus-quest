# GH-01 测评题生成说明

本目录只用于确定题目与测评结构，不生成或替换现有课件资源。

## 文件用途

- `question-generation-prompt.md`：总体测评设计规范，不直接提交 OpenMAIC。
- `pre-post-paired-prompt.md`：一次同时生成前测 A 卷与后测 B 卷，保证题位配对。
- `checks/GH-01-K01-prompt.md`：只生成“输入、输出和函数规则”即时检查。
- `checks/GH-01-K02-prompt.md`：只生成“坐标点与函数图像”即时检查。
- `checks/GH-01-K03-prompt.md`：只生成“图像的上升、下降与变化方向”即时检查。

## 推荐生成顺序

1. 提交 `pre-post-paired-prompt.md`，在 OpenMAIC 出现“点击审阅”后立即进入审阅页。
2. 只审阅大纲，不点击“确认并生成课程”。
3. 分别提交三个单知识点即时检查提示词，每次只接受一个 quiz。
4. 将通过检查的题目整理进网站题库；不直接采用模型原始输出。

## 必须人工或程序校验

- 前后测均为 6 题、60 分、`medium`，P01-P06 一一配对。
- 每对题的知识点、题型、函数族、符号结构、信息条数、步骤数和分值相同。
- 每个即时检查恰好 3 题，只覆盖标题对应的知识点。
- single 恰好一个正确答案；multiple 恰好两个正确答案。
- 逐题重新计算，答案字母、选项值和解析一致。
- 不出现“如图”“观察课件”等外部依赖。
- 不出现“需修正”“重新设置”等模型自我纠错痕迹。
- 章节、模块、知识点名称和 ID 不得更改。

## OpenMAIC 实测结论

`OpenRouter / auto` 能生成题目，但单次输出过长时会漏场景；即使提示词要求静默自检，也仍可能出现算术答案错误、多选题正确选项过多、区间方向写反或自我修正文字。因此生成结果必须经过校验，不能仅凭 `difficulty: "medium"` 或模型声明判定前后测等值。
