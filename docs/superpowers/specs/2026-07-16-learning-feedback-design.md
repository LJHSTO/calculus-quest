# 学习问题反馈与管理员面板整理设计

日期：2026-07-16
状态：已确认，待书面复核后实施

## 目标

把学生“记录”页中的单条学习反思改为可持续收集的“学习问题反馈”，在顶部主导航新增独立“反馈”页，并确保每次反馈都能在管理员面板中完整、清晰、可筛选地查看。

本次同时处理管理员面板中已经核实的信息不完整、命名含糊和重复排版问题，但不重写现有研究统计，不改变测验、学习快照、行为事件或 Agentic 路径数据的含义。

## 当前问题

- 学习反思正文只保存在最新学习快照的 `note` 字段中。
- `reflection_save` 分析事件只记录字符数，管理员用户详情接口也不返回快照正文，因此管理员目前看不到反思内容。
- 快照适合恢复学生当前状态，不适合保存多条、可检索的建议历史。
- 管理员面板的六张总览指标卡位于标签页之外，在所有标签中重复占用空间。
- “活跃趋势”页重复展示总览已有的每日趋势图。
- 用户详情只加载最近 200 条事件，却将 `detail.events.length` 标为“总事件数”。
- 用户表中的“覆盖单元”实际只统计出现过测验提交的单元，名称容易被理解为完整学习进度。
- 管理标签较多，现有换行布局和最小 500px 图表列在窄屏下容易拥挤或横向溢出。

## 选定方案

采用独立反馈数据表和专用接口。每次提交都是不可覆盖的独立记录；学习快照继续只负责学习状态恢复，行为事件继续只记录不含正文的分析元数据。

不采用以下方案：

- 把反馈正文写入行为事件：会把用户文本和高频分析日志混在一起，权限、筛选和导出边界不清晰。
- 继续写入学习快照：只能可靠表示最新状态，无法保留多次反馈历史。

## 学生端设计

### 导航与页面

- 顶部主导航在“记录”之后新增第 4 个“反馈”按钮。
- 新增 `feedback-view` 独立页面。
- “记录”页删除原“学习反思”卡片，并把页面说明中的“反思笔记”移除。
- 用户菜单仍保留“记录”，不额外复制反馈入口，避免同一功能出现两个次级入口。

### 表单字段

反馈类型为固定四类：

1. 学习内容
2. 课件反馈
3. 平台功能
4. 其他建议

正文必填，去除首尾空白后长度为 1–2000 个字符。前端显示剩余字数，后端重复验证，避免只依赖浏览器校验。

### 课件反馈对象选择

只有选择“课件反馈”时才显示反馈对象选择器。

- 默认选中学生最近正在学习的课件资源。
- 第一项始终是“全局课件反馈”。
- 其余项仅展示当前知识点的合法课件候选，来自当前 route 和运行时单元数据，不扫描或手工维护第二份资源清单。
- 选择器支持横向拖动、触摸滚动、点击和键盘选择；选中态必须有文字与边框，不只依赖颜色。
- 如果当前没有可识别的课件候选，只显示“全局课件反馈”，不得猜测旧场景序号或拼造资源标识。

提交成功后显示明确确认信息并清空正文；失败时保留正文和反馈对象，显示可重试错误。重复点击提交按钮时应在请求完成前禁用按钮，防止重复记录。

## 数据模型

新增 `feedback` 表，使用 `CREATE TABLE IF NOT EXISTS` 和新增索引完成兼容迁移，不修改或删除历史表和历史行。

建议字段：

| 字段 | 用途 |
| --- | --- |
| `id` | UUID 主键 |
| `user_id` | 登录用户 ID |
| `feedback_type` | `learning_content`、`courseware`、`platform`、`other` |
| `content` | 反馈正文 |
| `target_scope` | `global` 或 `courseware` |
| `chapter_id` / `module_id` / `unit_id` | 提交时学习位置 |
| `knowledge_point` | 学生可读的知识点名称 |
| `scene_type` | 课件表征类型 |
| `resource_file` | route 中的课件资源标识或文件引用 |
| `resource_title` | 提交时的学生可读课件标题 |
| `current_view` | 提交时所在主页面 |
| `created_at` | 服务端提交时间 |

反馈不是学生学习进度。现有“重置学习记录”流程不得删除 `feedback` 表中的历史记录，避免学生重置进度时一并抹掉已经提交给管理员的建议。

## 接口与数据流

### 学生提交

`POST /api/learning/feedback`

- 必须通过现有登录认证。
- 服务端使用类型白名单和正文长度校验。
- 课件反馈允许 `global`；选择具体课件时保存 route 派生的资源上下文。
- 服务端生成反馈 ID 和时间，写入独立反馈表。
- 另写一条不含正文的 `feedback_submit` 分析事件，只记录反馈 ID、类型、目标范围和正文字数，便于研究统计且不复制敏感正文。

### 管理查询

`GET /api/admin/stats/feedback`

- 使用现有管理员 Token 校验。
- 服从管理员面板的全局日期范围。
- 支持类型、目标范围、用户或正文关键词筛选。
- 返回 `summary` 与 `rows`：总反馈数、课件反馈数、反馈学生数，以及按时间倒序的反馈明细。
- 初版最多返回 1000 条；数据量增长后再引入分页，不提前增加复杂度。

## 管理员面板设计

### 问题反馈标签页

新增“问题反馈”标签，页面结构保持简洁：

- 三张指标卡：总反馈数、课件反馈数、反馈学生数。
- 一行筛选工具：反馈类型、全局/具体课件、用户或关键词搜索、导出 CSV。
- 一张明细表：时间、学生、类型、反馈对象、学习位置、正文。
- 正文列允许换行，长内容默认限制视觉高度并提供展开，不为反馈数据增加无实际价值的图表。
- CSV 包含完整正文和全部上下文字段。

初版不增加“待处理/已处理”状态。当前没有配套处理责任人、回复渠道或状态变更流程，空置状态字段只会制造冗余；未来需要工单闭环时再单独设计。

### 已核实的完整性与排版修正

- 把 `overview-metrics` 移入“总览”标签内容，只在总览展示。
- 从“活跃趋势”删除与总览重复的每日趋势图，保留小时分布和前后测明细。
- 用户详情增加独立事件总数查询，显示真实总数，不再用最多 200 条的数组长度冒充总数。
- 用户表“Quiz 数”改为“测验提交”，“覆盖单元”改为“测验覆盖单元”。
- 管理标签在窄屏采用单行横向滚动；图表栅格在窄屏变为单列，表格继续在自身容器内横向滚动。
- 管理页顶部时间筛选、刷新和退出按钮允许分组换行，避免挤压标题和状态文字。

这些调整只改变信息呈现和一个统计计数的准确性，不删除现有指标、接口或研究数据。

## 错误处理与兼容性

- 未登录提交返回 401；类型非法、正文为空或过长返回 400；数据库异常返回通用 500，不把内部路径或 SQL 暴露给用户。
- 管理查询无数据时显示明确空状态，不把接口错误渲染成“0 条反馈”。
- 新表迁移只新增结构；不得重建数据库或清空现有快照、测验、事件、用户和 Agent 决策。
- 旧快照中的 `note` 保留原样，升级后仍可加载，但学生端不再编辑或覆盖它；管理员反馈列表也不把旧反思伪装成新反馈。
- 子路径部署继续通过现有 `API_BASE`/资源 URL 机制访问，不新增以 `/` 开头的硬编码部署路径。

## 测试与验证

实施按测试先行完成，至少覆盖：

- 数据库初始化会新增反馈表且不会改变历史用户、快照、事件和测验数量。
- 插入多条反馈后均可保留，并能按用户、类型、目标范围和日期查询。
- 重置学习记录后反馈仍存在。
- 学生接口拒绝未登录、非法类型、空正文和超长正文。
- 管理接口需要管理员 Token，返回完整正文、用户、目标和学习上下文。
- 课件选择器只使用当前知识点合法候选；无候选时只显示全局反馈。
- 管理员真实事件总数不受最近 200 条详情限制。
- 严格 UTF-8 解码、所有修改 JS 的 `node --check`、现有 KG/Flow/KaTeX 测试、反馈专项测试全部通过。
- 启动服务进行浏览器 smoke：学生提交全局反馈和具体课件反馈；管理员能查看、筛选和导出；窄屏布局无明显溢出。
- 完成后比较工作分支与 `origin/main` 的已提交差异，检查本次改动是否与 GitHub 权威主线存在冲突或暴露已有回归；发现问题先修复并重新验证。
